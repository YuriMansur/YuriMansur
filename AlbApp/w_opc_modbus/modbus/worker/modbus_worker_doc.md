- Асинхронная коммуникация с Modbus TCP устройствами через pymodbus

   """
    Асинхронный воркер для низкоуровневой работы с одним Modbus TCP устройством

    Архитектура:
    - Создает два типа задач: command_loop (обработка разовых команд) и poll_loops (циклический опрос)
    - Использует asyncio.Queue для thread-safe передачи команд
    - Каждый poll_loop работает независимо в отдельной корутине
    """

    def __init__(self, plc_id: str, host: str, port: int = 502, device_id: int = 1):
        """
        Инициализация воркера

        Args:
            plc_id: Уникальный идентификатор устройства (для логирования и идентификации)
            host: IP адрес или hostname Modbus TCP устройства
            port: TCP порт (по умолчанию 502 - стандартный Modbus порт)
            device_id: Modbus Unit ID / Slave ID (адрес устройства на шине, обычно 1)
        """

    async def start(self, polls: list = None):
        """
        Запуск воркера

        Создает две группы асинхронных задач:
        1. Poll loops (циклические опросы) - если переданы в polls
        2. Command loop (обработка разовых команд) - основной цикл

        Args:
            polls: Список конфигураций циклических опросов
                   Формат: [{"name": "poll1", "address": 0, "count": 10, "interval": 1.0, "type": "holding"}]

        Примечание:
        - Poll loops запускаются в фоне (create_task)
        - Command loop блокирует выполнение (await) - это основной цикл воркера
        """

    async def _command_loop(self):
        """
        Основной цикл обработки разовых команд

        Работа:
        1. Устанавливает постоянное соединение с Modbus устройством
        2. Ожидает команды из очереди
        3. Выполняет команду (чтение/запись)
        4. Возвращает результат через future

        Архитектура:
        - Одно TCP соединение для всех команд (async with context manager)
        - Команды обрабатываются последовательно (FIFO из очереди)
        - При ошибке команда не останавливает цикл - ошибка передается в future
        """
    
    def _init_method_maps(self, client):
        """Инициализация словарей методов клиента """

    async def _read_modbus(self, client, type_, address, count):
        """
        Низкоуровневое чтение Modbus регистров

        Args:
            client: AsyncModbusTcpClient - установленное соединение
            type_: Тип регистров ("holding", "input", "coil", "discrete")
            address: Начальный адрес регистра
            count: Количество регистров для чтения

        Returns:
            list: Список значений регистров (int для registers, bool для bits)

        Типы регистров Modbus:
        - holding: Регистры хранения (16-бит, FC03) - для переменных
        - input: Входные регистры (16-бит, FC04) - для датчиков
        - coil: Дискретные выходы (1-бит, FC01) - для управления
        - discrete: Дискретные входы (1-бит, FC02) - для кнопок/датчиков
        """

    async def _write_modbus(self, client, type_, address, value):
        """
        Низкоуровневая запись Modbus регистров

        Args:
            client: AsyncModbusTcpClient - установленное соединение
            type_: Тип регистров ("holding", "holdings", "coil", "coils")
            address: Начальный адрес регистра
            value: Значение для записи (int для одиночного, list для множественного)

        Returns:
            bool: True при успешной записи

        Типы записи:
        - holding: Один регистр (16-бит, FC06) - value должен быть int
        - holdings: Множественные регистры (FC16) - value должен быть list[int]
        - coil: Один coil (1-бит, FC05) - value должен быть bool или 0/1
        - coils: Множественные coils (FC15) - value должен быть list[bool]
        """

    async def _poll_loop(self, poll: dict):
        """
        Циклический опрос одного диапазона регистров

        Работа:
        1. Создает отдельное TCP соединение (независимое от command_loop)
        2. Читает регистры с заданным интервалом
        3. Сохраняет результат в self.latest_data
        4. Игнорирует ошибки (не останавливает цикл)

        Args:
            poll: Конфигурация опроса
                {

                    "count": 10,                 # Количество регистров
                    "interval": 1.0,             # Интервал опроса в секундах
                    "type": "holding"            # Тип регистров (опционально, по умолчанию "holding")
                }

        Применение:
        - Мониторинг показаний датчиков
        - Отслеживание состояния устройства
        - Обновление данных для GUI в реальном времени

        Особенности:
        - Работает в фоне (не блокирует другие задачи)
        - Отдельное соединение (не мешает command_loop)
        - Автоматически переподключается при обрыве связи (async with)
        """

    async def request(self, command: tuple):
        """
        Публичный метод для отправки разовых команд

        Используется для выполнения разовых операций чтения/записи
        (в отличие от циклических опросов в poll_loop)

        Args:
            command: Команда в формате tuple
                Чтение: ("read", type, address, count)
                Запись: ("write", type, address, count, value)

        Returns:
            Результат выполнения команды (list для чтения, True для записи)

            result = await worker.request(("read", "holding", 0, 10))

            # Запись значения 100 в holding регистр по адресу 50
            await worker.request(("write", "holding", 50, 1, 100))

            # Запись нескольких регистров
            await worker.request(("write", "holdings", 100, 2, [123, 456]))

        Работа:
        1. Создает future для ожидания результата
        2. Помещает команду в очередь
        3. Ожидает выполнения командой в command_loop
        4. Возвращает результат или выбрасывает исключение
        """

    async def stop(self):
        """
        Корректная остановка воркера

        Порядок остановки:
        1. Устанавливает флаг _running = False (останавливает poll_loops)
        2. Отправляет команду остановки в command_loop (None, None)
        3. Отменяет все задачи циклических опросов

        После вызова:
        - command_loop завершится после обработки команды (None, None)
        - Все poll_loops завершатся после текущей итерации
        - TCP соединения будут автоматически закрыты (async with)
